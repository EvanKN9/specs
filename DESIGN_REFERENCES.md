# SPECS — Visual Direction

## Product

SPECS is a guided PC configuration application.

Users describe what they need from a computer — budget, workload,
performance target, storage, and other preferences — and SPECS produces
a recommended PC configuration.

The application helps users understand:
- why components were selected
- whether components are compatible
- how components relate to one another
- what changes when a component is replaced
- the tradeoffs between price, performance, power, and compatibility

## Brand

The user-facing product name is:

SPECS

The name refers both to:
- the user's requirements/specifications
- the resulting PC specifications

The existing project/repository name does not need to change.

## Design Goal

SPECS should feel like a deliberately art-directed hardware product,
not a conventional SaaS dashboard and not a stereotypical gaming site.

The experience should combine expressive editorial design with a
functional PC configuration tool.

Hardware itself should provide much of the visual richness.

Avoid attempting to make the interface interesting by adding excessive
cards, badges, pills, gradients, glass effects, or decorative UI.

## Primary Visual Asset

`src/assets/specs-hero.mp4`

This is the primary visual asset for the Home experience.

The video shows a premium gaming PC in a dark studio environment,
revealing its internal hardware.

Use it as visual content rather than placing it inside a generic card.

## Floria References

Use the Floria references for principles of:

- art direction
- dramatic negative space
- editorial pacing
- asymmetric composition
- strong typography
- imagery carrying the visual identity
- changing compositions rather than repeating one layout
- restraint

Do not reproduce the floral aesthetic or copy its layouts.

## Nothing References

Use the Nothing references for principles of:

- hardware as artwork
- cinematic product presentation
- product imagery integrated directly into composition
- dark and light sections within one visual system
- mixing expressive editorial typography with technical typography
- subtle technical/grid motifs
- restrained interface chrome
- generous whitespace

Do not copy Nothing's branding, navigation, glyphs, or exact layouts.

## Huly References

Use the Huly references for principles of:

- making functional product information visually expressive
- allowing UI/content to break rigid grids
- overlapping interface elements when meaningful
- large-scale typography
- presenting information-heavy software without defaulting to dashboards
- using actual product content as visual material

Do not copy Huly's product UI or branding.

## SPECS Design Principles

1. Hardware is visual content, not decoration.
2. Composition should carry more visual weight than UI ornament.
3. Use generous negative space.
4. Avoid repetitive grids of generic cards.
5. Different stages may use different compositions while remaining
   part of one visual system.
6. Mix editorial and technical typography intentionally.
7. Specifications must remain highly readable.
8. Compatibility relationships can become visual storytelling.
9. Component replacement should feel like comparing physical hardware,
   not choosing an option from a generic dropdown.
10. Motion should communicate assembly, relationships, selection, or
    state changes rather than exist only for decoration.
11. Preserve accessibility and usability.
12. Avoid common AI-generated website patterns.

## Avoid

- generic SaaS dashboards
- excessive rounded cards
- floating metric badges
- excessive pills
- purple/blue AI gradients
- glassmorphism
- decorative blobs
- meaningless animations
- repeating the same section composition
- stereotypical RGB gaming aesthetics
- copying any reference directly
